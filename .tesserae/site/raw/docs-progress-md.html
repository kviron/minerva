    Minerva progress

    Last updated: 2026-07-12

    Current state

    The approved Identity foundation, global-navigation slice, and Projects RBAC foundation are implemented and verified. Authenticated users now land on Dashboard, the sidebar obtains a server-filtered menu through the Navigation feature, and the shared Projects application service can create a project atomically with its built-in roles, permission grants, creator membership, and audit event.

    Completed

    • Confirmed the workspace began empty.
    • Installed the official Superpowers plugin for Codex.
    • Installed Tesserae 0.10.1 as an isolated uv tool.
    • Initialized the Git repository.
    • Created the first canonical product, architecture, ADR, roadmap, and backlog documents.
    • Audited the proposed MVP with Superpowers principles and reduced the first MCP boundary to documentation operations.
    • Initialized and compiled the local Tesserae knowledge graph.
    • Registered Tesserae as the enabled minerva-memory Codex MCP server.
    • Created the vertical MVP delivery plan and detailed TDD plan for Slice 1.
    • Scanned the canonical documents and plans for placeholders and internal scope conflicts.
    • Completed the final interactive MVP audit and resolved project-bound invitations, immediate OAuth/MCP revocation, complete immutable document snapshots, and reproducible foundation setup.
    • Added ADR 0005 for MCP resource binding and immediate token revocation.
    • Audited the MVP information architecture and drafted the eight-screen shadcn-vue Figma prototype specification.
    • Received user approval for the written UX/UI prototype specification and prepared its detailed Figma implementation plan.
    • Added ADR 0006 to replace pnpm with Bun as the package manager before application implementation begins.
    • Created the buildable Nuxt page-file skeleton for the approved MVP route map without UI or business behavior.
    • Added public empty route stubs for Terms of Service and Privacy Policy under /legal.
    • Added secure password recovery to the MVP design while preserving invitation-only registration.
    • Added a safe Tesserae refresh wrapper that prevents the recurring Windows WinError 183 workflow failure.
    • Added public empty route stubs for password recovery under /auth.
    • Added a local PostgreSQL 17 Docker Compose service with loopback-only access, persistent storage, and a readiness health check.
    • Approved the Better Auth identity, optional profile, dynamic contact, privacy, and project-role data model, with phone authentication deferred until an SMS provider is selected.
    • Preserved shared input styling when Chromium autofills credentials by overriding its text fill and covering its protected autofill background with a theme-aware inset surface.
    • Added the approved static password-recovery request screen, matching sign-in styling and linked bidirectionally with /auth.
    • Added the approved static new-password form on the tokenized reset route without exposing or processing the token.
    • Added validated server environment configuration and unit/integration/browser test foundations for the Identity backend.
    • Added isolated PostgreSQL test infrastructure, local Mailpit, and a database readiness endpoint.
    • Added the Better Auth factory with PostgreSQL/Drizzle, email-password and username support, persistent sessions, database rate-limit storage, account status fields, password-reset settings, and the first reviewed migration.
    • Added an advisory-lock-protected, idempotent first-super_admin bootstrap service and an interactive CLI that never accepts or prints the password as an argument.
    • Added normalized email-or-username sign-in, generic credential failures, database-backed HMAC rate limiting, durable sessions, active-account enforcement, and a server-side session guard for protected Nitro handlers.
    • Added enumeration-safe password recovery through SMTP/Mailpit with a 30-minute single-use token, reset throttling, sanitized delivery failures, and automatic session revocation after reset.
    • Connected the existing shadcn-vue authentication forms without redesign, added client session middleware, guest/auth redirects, logout verification, pending/error states, and complete browser journeys for sign-in and recovery.
    • Verified the completed Identity foundation with a frozen dependency install, two idempotent migration runs, 9 unit tests, 22 PostgreSQL integration tests, 8 browser journeys, Nuxt typecheck, and a production build.
    • Used the pinned native Mailpit 1.30.0 binary for final SMTP verification because the current Docker Desktop port proxy accepted the local SMTP connection but did not relay the server greeting; Docker Compose remains the canonical development configuration.
    • Completed the Identity functional refactor with shared ObjectConst values and derived types, scenario-based module grouping, pure Result classification, and dependency-injected rate-limit, sign-in, recovery, and session effects.
    • Added the repository-local functional-typescript skill and the repository Nuxt MCP configuration.
    • Verified the Identity refactor on 2026-06-29 with a frozen dependency install, 24/24 unit tests across 9 files, 22/22 PostgreSQL integration tests across 6 files, Nuxt typecheck, a production build, an unchanged Drizzle tree, a valid repository skill, the enabled repository Nuxt MCP, and a clean diff check. After removing a stale worktree-local Nuxt prepare process, a cold-start browser run passed 7/8 because the unchanged guest redirect exceeded its timeout; that guest case then passed twice in isolation, and the final full browser run passed 8/8.
    • Established the Nuxt-native feature-module convention with Identity as the reference implementation: API, model, and UI separation; vee-validate/Zod forms; explicit imports through the feature public API; and page-owned reset-route token handling, with visual and server behavior unchanged. Verification completed with a frozen install (1,013 installs across 1,174 packages, no changes), 58/58 unit tests across 14 files, 22/22 PostgreSQL integration tests across 6 files, 8/8 browser journeys, Nuxt typecheck, a production build, an unchanged Drizzle tree, and a clean diff check. The requested Docker Compose start exited 1 because another healthy Minerva PostgreSQL test container already owned port 5433; verification used that healthy PostgreSQL service and its healthy pinned Mailpit 1.30.0 companion on ports 1025/8025.
    • Made Nuxt pages and application Nitro APIs authenticated by default; approved public sign-in, recovery, invitation, legal, and readiness routes remain public, while global administration uses the server-resolved superAdmin flag.
    • Authorization now uses a browser-safe typed session boundary, request-scoped session reuse, and a single API access vocabulary without changing access behavior.
    • Added the protected Dashboard landing page, a shared authenticated-page development placeholder used only by Dashboard and Project Credentials, and a typed global Navigation feature. The server returns Dashboard, Projects, and Settings to every authenticated user and adds Administration only for strict superAdmin === true; the sidebar localizes stable labels, resolves icons through a closed Lucide registry, uses the design-system SidebarMenuSkeleton, and keeps Credentials outside global navigation and MCP. Verification on 2026-07-02 passed 167/167 unit tests, 22/22 PostgreSQL integration tests, 17/17 single-worker browser journeys, Nuxt typecheck, and the production build.
    • Added the Identity feature's public CurrentUserMenu to the authenticated sidebar, backed by the real safe Better Auth session projection for name, email, and an optional validated avatar with an initials fallback. The menu links to the profile, logs out by revoking the server session, and removes the demo Billing and Notifications actions. Isolated the browser rate-limit fixture so authentication E2E scenarios do not share throttle state. Verification on 2026-07-04 passed bun run test:unit (209/209 tests across 33 files), bun run test:integration (22/22 tests across 6 files), bun run typecheck, bun run build, and bun run test:e2e (18/18 browser journeys).
    • Replaced the authenticated header's template GitHub link with the shared localized light, dark, and system theme selector. Verification on 2026-07-04 passed the complete unit suite (214/214 tests across 35 files), Nuxt typecheck, and the production build.
    • Added the Projects RBAC foundation: immutable admin, editor, and viewer role templates; additive PostgreSQL tables and constraints for projects, roles, permissions, memberships, and audit events; and a validated shared project-creation service that locks and rechecks the creator account before atomically creating the complete project graph. Database constraints preserve membership history and enforce normalized project metadata. Verification on 2026-07-05 passed bun run test:unit (232/232 tests across 37 files), bun run test:integration (30/30 tests across 7 files), bun run typecheck, bun run build, and bunx drizzle-kit check --config drizzle.config.ts. The production build retained three upstream bundler warnings (one Nuxt module-preload sourcemap warning and two VueUse pure-annotation warnings) plus Node's DEP0155 deprecation warning. The reviewed 0001_projects_rbac_foundation.sql migration is additive and contains no destructive or Identity-table operations.
    • Added one reusable project-status filter for both the member and administration project tables. Shared tabs select all, active, or archived projects through a pure typed transformation, and a distinct design-system empty state explains when the selected status has no matches. Verification on 2026-07-10 passed all 15 project client tests, Nuxt typecheck, the production build, and a clean focused diff check.
    • Added a shared settings section header with the localized title, description, and existing category tabs across all settings routes. Its compact spacing relies on the layout's existing vertical padding and avoids stacked page-level padding. Verification on 2026-07-10 passed all 4 settings navigation tests, Nuxt typecheck, and a clean focused diff check.
    • Unified list-page spacing across member projects, administration projects, and administration users: page views now rely on the default layout for vertical padding and use a compact internal gap instead of stacking a second py-6. Verification on 2026-07-10 passed all 24 related project, administration, and settings client tests plus Nuxt typecheck.
    • Added the protected project overview slice. A member-scoped endpoint resolves a safe project projection only when an active membership has project.view, returns the same 404 for missing and inaccessible projects, and exposes role, active-member count, and permission codes for UI composition. Project routes now provide Overview, Pages, and permission-aware Settings navigation; Pages and Settings remain explicit placeholders until their document, member, role, and audit services are implemented. Verification on 2026-07-10 passed 20 project client tests, Nuxt typecheck, and the production build. The new PostgreSQL integration test is ready but could not run because the configured test database endpoint at 127.0.0.1:5433 was unavailable.
    • Made every project-table row open its project in both the member and administration views. Rows remain keyboard accessible through Enter and Space and expose an explicit accessible label. Verification on 2026-07-10 passed 21 project client tests and Nuxt typecheck.
    • Added a read-only super-administration user detail page. The Users table now opens users from every row by mouse, Enter, or Space; the endpoint and page are guarded by requireSuperAdmin and project only safe fields from Better Auth's user table. No account, session, token, password, or block-reason data is selected or exposed. The list now uses administration/users/index.vue, preventing Nuxt from treating it as the parent of the dynamic user-detail route. Verification on 2026-07-10 passed 8 administration client tests, 32 API-authorization tests, Nuxt typecheck, and the production build.
    • Added a contextual current-project selector to the global sidebar. It derives the project id from project routes, loads a member-scoped project list only while a project is active, and opens a dropdown of accessible projects for switching context; outside a project it shows a linkable “Выберите проект” placeholder. Verification on 2026-07-10 passed the focused selector tests and Nuxt typecheck.
    • Replaced the global main sidebar navigation on project routes with project-scoped Credentials, Documentation, and Settings links while preserving the current-project selector. Moved global Settings into a secondary navigation group pinned above the user menu, following the shadcn-vue dashboard-01 sidebar composition. Verification on 2026-07-11 passed 8 focused client tests and Nuxt typecheck.
    • Consolidated project navigation in the sidebar by adding Overview and removing the duplicated horizontal Overview, Documentation, and Settings tabs from the shared project shell. The exact Overview active state no longer overlaps nested project routes. Verification on 2026-07-11 passed 9 focused project client tests and Nuxt typecheck.
    • Approved the encrypted Project Credentials design: projects start with no predefined categories; Project Admin creates single-level categories, grants allow access to roles or individual members, and retains non-removable access to every category. Credentials support encrypted login/password values and ordered dynamic text, secret, URL, and note fields; list responses stay masked and MCP remains excluded. Added accepted ADR 0010 and a seven-slice TDD implementation plan.
    • Completed Project Credentials Slice 1. Added eight stable permission codes with Admin-only built-in defaults, closed dynamic-field types, five project-scoped credential/category/grant tables, authenticated-encryption envelope constraints, same-project composite foreign keys, recoverable archive metadata, and an additive 0002_project_credentials_foundation.sql migration that backfills existing built-in Admin roles without granting Editor or Viewer. Verification passed 8 focused unit tests, 5 PostgreSQL schema/integrity tests, Nuxt typecheck, and drizzle-kit check.
    • Completed Project Credentials Slice 2. Added an injected AES-256-GCM boundary with random 96-bit nonces, appended authentication tags, deterministic project/category/credential/field associated data, generic decryption failures, and versioned 32-byte keys. Credential key validation is strict but isolated from the existing server environment until the Credentials runtime is composed. Added rotation, backup, and recovery operations. Verification passed the full 277-test unit suite, Nuxt typecheck, and a focused secret-leak scan; only the documented non-secret .env.example key remained.
    • Completed Project Credentials Slice 3. Added shared server-side category ACL evaluation and transactional create, update, archive, and grant-replacement services. Effective access is the union of the actor's role and individual membership grants; roles with the non-removable Admin management permission retain implicit access. Grant validation rejects inactive or foreign-project subjects before replacing existing rows, revocation applies on the next query, inaccessible categories return the same safe result as missing ones, category archival cascades recoverably to active credentials, and audit metadata contains only grant counts. Verification passed 3 PostgreSQL credential integration tests, the full 277-test unit suite, and Nuxt typecheck.
    • Completed Project Credentials Slice 4. Added transactional encrypted credential create/update/archive services, ordered dynamic fields, explicit keep/replace/clear commands, safe masked list contracts, and separately authorized one-field reveal with secret-free audit events. Thin project-scoped Nitro handlers derive actor/project/channel from session and route; strict Zod bodies reject client actor fields, reveal is no-store and rate-limited, and runtime encryption keys are loaded only on Credentials requests. No MCP capability was added. Verification passed 279/279 unit tests, 4/4 credential PostgreSQL integration tests, Nuxt typecheck, and the production build with the known upstream sourcemap, VueUse annotation, and Node DEP0155 warnings.
    • Completed Project Credentials Slice 5. Replaced the credentials placeholder with a Nuxt-native feature view and added strict category-management API adapters, project-scoped Nitro endpoints, safe client state, the no-category Empty CTA, and a titled shadcn-vue Sheet for create/edit/archive. Project Admin can grant access through roles or individual active memberships; the built-in Admin checkbox remains visibly selected and disabled, archive requires AlertDialog confirmation, and all loading/save failures are localized without raw errors. Existing Sheet, Field, Checkbox, AlertDialog, Empty, Skeleton, and Button primitives were reused without registry changes. Verification passed 282/282 unit tests, focused category ACL PostgreSQL integration tests, Nuxt typecheck, and the production build with the known upstream warnings.
    • Completed Project Credentials Slice 6. Added the masked credential Table with title, category, login, password, changed-at, and a rightmost three-dot menu containing only Edit. Safe client-side search and category filtering operate exclusively on masked list data. The titled editor Sheet supports create and edit, ordered dynamic text/secret/URL/note fields, and explicit keep/replace/clear operations; all plaintext drafts are cleared when it closes. Creation and row editing are gated by server-derived permission capabilities rather than role names. Verification passed 286/286 unit tests, all 11 credential integration and focused client tests, Nuxt typecheck, and the production build with the known upstream warnings.
    • Completed Project Credentials Slice 7 and the approved Credentials implementation plan. Added a single-worker browser journey covering Admin category creation and Viewer grant management through the real UI, masked credential creation, authorized one-field reveal with no-store, denied Viewer mutation, immediate access revocation, and indistinguishable cross-project 404 responses. Updated the former credentials-placeholder identity journey and allowed the SMTP-backed recovery integration suite its observed local delivery latency without changing production behavior. Final verification passed 286/286 unit tests, 36/36 PostgreSQL integration tests across 11 files, 19/19 single-worker browser journeys, Nuxt typecheck, the production build, Drizzle migration validation, and a focused production-source secret-leak scan.
    • Fixed Credentials category-creation visibility by exposing canCreateCategories independently from category access management. Users with credential_categories.create now see the create action even without credential_categories.manage_access; their Sheet omits grant and archive controls and does not call the forbidden grant-replacement endpoint. Project Admin retains the complete management experience. Verification passed 287/287 unit tests, 12 focused credential client/integration tests, Nuxt typecheck, and the production build.
    • Fixed local credential creation after the Credentials migration was applied. The failure was caused by absent encryption-key environment variables, so a safe idempotent credentials:key:init command now generates a private 32-byte local key in .env, never prints key material, and refuses to overwrite partial or existing configuration. The local key was initialized, and the credential editor save button is explicitly non-submitting to prevent native page reloads. Verification confirmed one configured key version, passed 288/288 unit tests, Nuxt typecheck, and the production build.
    • Revised the Credentials table under accepted ADR 0011. Authorized lists now decrypt and display login values with compact copy controls while PostgreSQL storage remains encrypted; list responses are no-store. Passwords remain absent from list contracts and use compact show/hide and copy buttons backed by the existing authorized, rate-limited reveal endpoint. Copy feedback is ephemeral and password plaintext remains only in memory. Verification passed 12 focused credential client/integration tests, 288/288 unit tests, Nuxt typecheck, and the production build.
    • Added permission-aware credential removal to the row menu. Edit and Delete now have Lucide icons; Delete opens a titled shadcn-vue AlertDialog asking for explicit confirmation and explaining recoverable archival. Confirmation calls the existing protected DELETE endpoint, clears any revealed password for the row, and refreshes the table; cancellation leaves the record unchanged. Verification passed 13 focused credential tests, 289/289 unit tests, Nuxt typecheck, and the production build.
    • Added last-editor context to credential rows. Hovering or keyboard-focusing the changed-at date opens a shadcn-vue HoverCard with the updater's Avatar, initials fallback, and display name. The server list projection joins only the updater's name and avatar, validates avatar URLs, and exposes no email or other profile data. Verification passed 13 focused credential tests, 289/289 unit tests, Nuxt typecheck, and the production build.
    • Refined the credential last-editor HoverCard hierarchy: the updater's name is now the larger primary line above a smaller muted “Последнее изменение” caption. Focused UI tests and Nuxt typecheck passed.
    • Refactored the Credentials client into feature-scoped actions under accepted ADR 0012. CredentialsActions now owns asynchronous commands, pending/error handling, concurrency keys, cancellation signals, safe errors, and narrow injected API/clipboard capabilities; a route-level provider exposes one instance to the feature UI. Category and credential state models retain only synchronous draft/projection transformations, while child components invoke actions without importing API adapters or $fetch. Verification passed 295/295 unit tests across 58 files, 4/4 focused PostgreSQL integration tests, Nuxt typecheck, and the production build. The complete Credentials Playwright journey passed in 17 seconds after its grant-revocation step was made deterministic by awaiting the grants response; the Playwright command itself still reaches the outer 180-second timeout while stopping the Nuxt test web server after the successful scenario.
    • Strengthened the Credentials category boundary across storage, server, and client with composable shared domain projections and named request/response contracts. Drizzle query projections and server commands now resolve to the same safe category/list/body/grants types while server-only actor context and storage-only metadata remain isolated; the client uses an explicit narrow API interface with runtime parsing for every successful response, and server Zod schemas are type-checked against the shared request DTOs. Verification passed 7 focused category API/action tests and Nuxt typecheck.
    • Corrected the Credentials client action boundary by splitting category management into CredentialCategoryActions. CredentialsActions now depends only on credential state, credential API, and clipboard capabilities; category actions depend only on category state and category API. The feature provider exposes both narrow action objects, and cross-entity refresh after category archival is composed explicitly by the view. Architecture tests prevent either class from importing the other entity's state or API. Verification passed all 18 focused Credentials client tests and Nuxt typecheck.
    • Removed credential store access from CredentialsActions. Credential actions now accept explicit commands, identifiers, and values, perform only API/clipboard effects, and return rows, revealed values, or copy keys; they never construct drafts or mutate UI state. Credentials state has its own provider boundary, and views explicitly create commands, apply returned projections, manage reveal/copy feedback, and open editors. Architecture tests prohibit CredentialsState and this.state in the action class. Verification passed all 18 focused Credentials client tests and Nuxt typecheck.
    • Simplified asynchronous action cancellation by removing the ActionExecutionContext wrapper. BaseActions now passes an AbortSignal directly to effects, and Credentials/category actions and API adapters expose that purpose explicitly through signal parameters. Verification passed 21 focused shared-action and Credentials tests and Nuxt typecheck.
    • Removed category store access from CredentialCategoryActions. Category actions now accept explicit save commands or category IDs and return management projections/results without reading drafts, selecting categories, or applying state. Category state has its own provider boundary and UI composition applies action results explicitly. Architecture tests prohibit CategoryManagementState and this.state in the action class. Verification passed 21 focused shared-action and Credentials tests and Nuxt typecheck.
    • Migrated Credentials UI state to a Pinia setup store using the official @pinia/nuxt integration. CredentialsActions remains a stateless API/clipboard service that accepts explicit parameters and returns results; UI consumers explicitly apply returned rows and values to useCredentialsStore, which owns projections, editor drafts, revealed values, and copy feedback. Removed the manual credentials state injection boundary and added isolated Pinia store tests plus architecture guards preventing action classes from importing Pinia or state. Verification passed 23 focused shared-action and Credentials tests and Nuxt typecheck.
    • Simplified the concrete Credentials and category action services by removing constructor-injected API/clipboard dependency objects. The classes now call their feature API adapters and browser clipboard directly while remaining store-free and accepting all business data through method arguments; tests replace adapters with module mocks instead of shaping production constructors around test injection. Verification passed 23 focused shared-action and Credentials tests and Nuxt typecheck.
    • Standardized control-flow readability across the Credentials feature: every if branch now uses explicit braces, including early returns, parser failures, async API branches, store transformations, provider guards, and UI handlers. Removed the remaining inline conditional handler from the Vue template. Verification passed 23 focused shared-action and Credentials tests and Nuxt typecheck.
    • Reworked BaseActions.createAsyncAction to accept one declarative AsyncActionDefinition object with required name and run fields plus optional idGetter and options. Migrated all Credentials/category actions and shared action tests to the named-field syntax without changing cancellation, concurrency, pending, safe-error, or analytics behavior. Verification passed 23 focused shared-action and Credentials tests and Nuxt typecheck.
    • Made BaseActions.createSyncAction symmetric with the async action API through a single declarative SyncActionDefinition object containing required name and run fields plus optional idGetter and options. Preserved sync tracking and safe-error behavior and added direct contract coverage. Verification passed 24 focused shared-action and Credentials tests and Nuxt typecheck.
    • Accepted ADR 0013 as the project-wide client action rule. Every effectful feature owns entity-scoped stateless actions under model/actions; actions receive business data explicitly, call concrete API/browser effects through BaseActions, return safe results, and never access Pinia. Stores own projections and drafts without performing effects, while UI composition explicitly applies action results. ADR 0013 supersedes the state-coupled and injected-capability-by-default portions of ADR 0012.
    • Simplified the Credentials Pinia model from a setup store with many refs to a conventional Option Store with one typed state() object and explicit actions. Replaced the hidden editor-open watcher with setEditorOpen, which clears plaintext deterministically when the Sheet closes. Verification passed 25 focused shared-action and Credentials tests and Nuxt typecheck.
    • Removed type and non-null assertions from the Credentials Pinia state. A contextual CredentialsState return type now validates the complete state() object, allowing nullable fields, closed-set modes, arrays, and records to use plain initial values; field movement now narrows the selected item explicitly. Verification passed 25 focused shared-action and Credentials tests and Nuxt typecheck.
    • Established a project-wide TypeScript typing rule in the agent instructions, architecture documentation, and functional TypeScript skill: prefer contextual types and narrowing, prohibit assertions used only to silence the compiler, preserve as const for literal closed sets, and isolate justified assertions at validated external boundaries.
    • Migrated credential category management from the ref/computed createCategoryManagementState factory to a conventional typed Pinia Option Store. Category projections, permission capabilities, and editor drafts now live in useCategoryManagementStore; Vue provide/inject remains limited to stateless action-service instances. Consumers use direct store properties without .value, and first-category access is narrowed without non-null assertions. Verification passed all 27 focused Credentials client tests and Nuxt typecheck.
